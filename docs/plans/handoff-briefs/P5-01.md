## 1. Task
ID P5-01, role qa-engineer. On a quiet machine (no other agent running), run the complete verification of the branch tip and the static technical acceptance checks, and write the verification report per ADR-005 §4.2. Report only — no code changes, no commits. You hold the RUNTIME lock (and effectively the whole VM).

## 2. Git rules
Work on the current branch `feature/hardware-service-decision-copilot`. Check it first with `git branch --show-current`, and stop if it differs. Do not create branches, do not push, do not commit, do not modify tracked files. NEVER read/print `.env` or env values.

## 3. Files
None tracked. Everything under `app/qa-artifacts/P5-01/` (gitignored).

## 4. Context
Checks (run in `app/`, each logged to its own file):
1. `npm ci` (clean install) — exit 0.
2. `npm run typecheck`, `npm run lint` — exit 0.
3. `npm test` — counts (files/tests passed/failed/skipped); must be offline (fetch guard) — TAC-005-03.
4. `npm run build` — exit 0, count warnings (expect 0) — TAC-02.
5. `npm run test:contract` — all C-01…C-08 (record per test).
6. `npm run test:e2e` (chromium all + firefox/webkit `@smoke`) and `npx playwright test --project=failure` — record per project; WebKit may fail to launch for missing system libraries (environment; record the exact error, do not count as app failures).
7. Reliability: `npx playwright test --project=contract --grep "C-04|C-07|C-08" --repeat-each=3` and `npx playwright test --project=chromium --grep "E-0[3-8]|E-1[01]" --repeat-each=3` — pass rate per scenario; from the E2E runs extract `ttfc_ms` annotations (HTML report data) and compute max and p95 TTFC — TAC-06 (< 60 s each).
8. Static checks:

   - TAC-07: `grep -E '"(next-auth|drizzle-orm|postgres|@vercel/blob|redis|resumable-stream|botid|@ai-sdk/gateway)"' package.json` → nothing.
   - TAC-004-01: `grep -rnE "localStorage|sessionStorage|indexedDB|document\.cookie" components lib --include=*.ts --include=*.tsx | grep -v "\.test\."` → nothing.

   - TAC-005-06: `find tests -type f \( -iname "*.png" -o -iname "*.jpg" -o -iname "*.jpeg" -o -iname "*.webp" -o -iname "*.heic" \)` → nothing generated (captures contain JSON only).

   - ADR-005 §8 "No test mode": `grep -rnE "isTestEnvironment|PLAYWRIGHT|models\.mock" app components lib` → nothing.

Run checks 1–8 in order; for failures capture artifacts (copy `playwright-report/` and `test-results/` per run into `qa-artifacts/P5-01/<run>/` before the next run wipes them). Do not stop at the first failure — run everything, then report. Stop servers; ports free at the end.

As listed. RUNTIME allowed. No `curl`, no code edits.

All checks executed and reported.

## 9. Report format (ADR-005 §4.2)
Separate lines: install; typecheck; lint; unit+integration (counts); build (warnings); contract (per test); E2E per project (passed/failed/skipped, fixme list with reason); failure project; reliability table (scenario, passes/3); TTFC max/p95; each static check (PASS/FAIL + evidence); unused vendored files; failure blocks (name, project, error, artifact path, diagnosis spec/app/model/infra); memory; ports. No prose beyond this.

## RULE (from FIX-09)
Never run two Playwright processes (test runner, capture, or a second project run) at the same time in `app/`: they share `test-results/`/`playwright-report/` and corrupt each other (ENOENT on traces, wiped artifacts). Run every Playwright command strictly sequentially and copy artifacts to `app/qa-artifacts/<task>/` after each run. Server logs (`ai_call` JSON lines with outcome, totalMs, msToFirstChunk, finishReason, reasoningTokens) are now piped into the Playwright output — include them in your diagnosis of any failure. E2E runs in the pl-PL locale (FIX-10).
