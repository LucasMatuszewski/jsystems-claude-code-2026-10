# P23 - Mapa aplikacji i karty API frameworka

Przeczytaj nasze sprawdzone raporty. Zbuduj krótką mapę aplikacji i dwie karty API na rzeczywistych granicach modułów. Nie wczytuj wszystkich źródeł do jednej sesji. Sprzeczne lub nieudokumentowane twierdzenia sprawdzaj w oryginale.

Karta zawiera: repozytorium i commit, typ oraz dokładną sygnaturę, odpowiedzialność, przykład użycia z istniejącego callera, zachowanie błędów i ograniczenia potwierdzone kodem. Dołącz ścieżkę, zakres linii, symbol i hash pliku. Oznacz, czy twierdzenie pochodzi ze źródeł, użycia czy uruchomienia. Gdy źródło zależności jest niedostępne, zapisz pytania i opis wywnioskowany z użycia; nie wymyślaj przeciążeń ani parametrów.

Oddaj mapę w `docs/discovery/architecture.md`, karty pod `docs/discovery/api/` i indeks dowodów. Zapisz pokrycie: jakie pliki i obszary przeczytano, jakie pominięto i czego nadal nie wiemy. Mapa ma pomóc następnemu agentowi wybrać potrzebny kod do konkretnej zmiany.
