# P26 - PRD i ADR dla jednej zmiany w istniejącej aplikacji

Pracuję w repozytorium aplikacji, którą już rozpoznaliśmy. Użyj zainstalowanej umiejętności `write-prd` dla jednej funkcji, naprawy albo refaktoringu. Najpierw ustalmy problem, użytkownika, aktualne zachowanie, oczekiwany wynik, ograniczenia i zakres poza zadaniem. Czytaj naszą mapę i potrzebny kod; nie traktuj materiałów kursowych ani historycznych przykładów jako wymagań.

Zapisz PRD tej zmiany we wskazanym miejscu w aplikacji. Oddziel fakty o legacy od nowego wymagania. Jeśli podejmujemy decyzję architektoniczną, użyj `write-adr`, porównaj realne opcje i odnotuj naszą decyzję. Nie pisz ADR dla samego wykonania oczywistego polecenia.

Przygotuj plan z plikami, zależnościami, właścicielem, testem lub dowodem oraz punktami review. Nie implementuj w tym kroku. Po uzgodnieniu przejdziemy przez test, małą zmianę, weryfikację, niezależny review i PR. Skill ma być widoczny w narzędziu; jeśli go brakuje, wróćmy do ćwiczenia instalacji.
