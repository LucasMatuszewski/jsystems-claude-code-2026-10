Pracujemy nad AI Chat opisanym w aktualnym PRD i ADR. Zaimplementuj tylko najbliższy zatwierdzony pionowy fragment: wysłanie wiadomości z React do backendu i stopniowe wyświetlenie odpowiedzi. Najpierw sprawdź stan repozytorium, istniejące testy, wersje AI SDK oraz faktyczne polecenia z manifestu. Jeśli kontrakt endpointu albo zakres PRD jest niejasny, zatrzymaj zależną część i zadaj konkretne pytanie.

Zastosuj Red -> Green -> Refactor. Wyprowadź testy z kryteriów akceptacji: poprawne wysłanie, pusta wiadomość, przyrost odpowiedzi i awaria dostawcy. Uruchom nowe testy przed kodem produkcyjnym i zachowaj ich dokładny wynik. Nie uznawaj braku zależności, błędu importu lub niedziałającej infrastruktury za oczekiwany Red. Implementuj minimum, uruchom ten sam test i dopiero potem refaktoryzuj przy zielonej weryfikacji. Nie zmieniaj asercji tylko po to, aby uzyskać sukces.

Rozdziel pracę zgodnie z przyjętą macierzą. `be-developer` otrzymuje endpoint i integrację dostawcy, `fe-developer` otrzymuje UI i `useChat`; `qa-engineer` przegląda scenariusze i dowody. Nie uruchamiaj pracy równoległej nad tym samym plikiem, kontraktem ani lockfile. Gdy jeden agent wystarcza do tego fragmentu, uzasadnij to zamiast mnożyć procesy.

Przed odtworzeniem mocka odpowiedzi usługi wykonaj świeże, autoryzowane żądanie w środowisku testowym na danych syntetycznych. Zachowaj pełny, bezpieczny status, nagłówki i body oraz datę, wersję i żądanie bez poświadczeń. Jeśli nie można uzyskać bezpiecznego capture, zgłoś brak warunku zamiast wymyślać protokół. Unit może zastępować zależności; integration zastępuje tylko zewnętrzny model; końcowe E2E działa na prawdziwym stosie.

Sprawdź aktualne API `useChat` i serwerowego streamingu przez Context7. Nie mieszaj przykładów starszego `ai/react` z nowym transportem. Sekret dostawcy pozostaje wyłącznie na serwerze. Treść modelu traktuj jako niezaufaną. Nie dodawaj logowania, bazy ani nowych funkcji poza PRD.

Po zielonych testach osobno potwierdź uruchomienie aplikacji. Przejdź rzeczywisty przepływ w przeglądarce: wpisz wiadomość, wyślij, zobacz przyrost odpowiedzi, zadaj drugie pytanie i sprawdź zachowanie po błędzie. Zachowaj screenshot oraz błędy konsoli. Raportuj pliki, kryteria, Red i Green, wyniki ze zliczeniem pominięć oraz ograniczenia. Commit wykonuj dopiero po przejrzeniu diffu, dodając jawne ścieżki plików; publikację i merge uzgadniamy osobno.
