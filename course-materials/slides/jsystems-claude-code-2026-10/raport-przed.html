Wniosek przewodni

Grupa zna już Claude Code, ale większość ocenia swój poziom jako początkujący. Największą wartość daje powtarzalny sposób pracy z agentem: kontekst i instrukcje, PRD i ADR, delegowanie do sub-agentów, testy i review, a nie kolejny przegląd funkcji.

Różnorodny stos

Python i SQL (po 6 osób), C#/.NET (3), Java i PHP (po 2) oraz pojedynczo C++, Go i TypeScript. Przykłady kursowe używają TypeScript, a wzorce pracy przenoszą się na każdy stos. Cztery osoby pracują głównie z danymi (ETL, BI, Data Science).

03 · Oczekiwania i problemy

Co ma zostać po kursie

Odpowiedzi otwarte podało 7 osób; streszczenie bez cytatów.

Oczekiwane rezultaty

  • 01
    Pełne wykorzystanie agentówZaawansowane funkcje i sposoby pracy z Claude Code; agenci, którzy sami realizują wieloetapowe zadania, testują i poprawiają kod.
  • 02
    CI/CD i ticketyPełna integracja z pipeline, automatyczne rozwiązywanie zgłoszeń i dobór modeli do zadań: tańsze tam, gdzie wystarczą, najmocniejsze tam, gdzie są potrzebne.
  • 03
    Bezpieczne automatyzacjePowtarzalne automatyzacje w Pythonie, PowerShellu, SQL i API, także on-premises; agent wspierający administrację IT pod kontrolą człowieka.
  • 04
    Mniej ręcznego koduAplikacje webowe w chmurze, rozwiązania no-code oraz agent, który wypełnia formularze w przeglądarce.

Problemy i najbardziej czasochłonne zadania

  • 05
    Koszt i zapętlone agentyMarnowanie tokenów na agentach, które krążą w pętli. Potrzebne limity, checkpointy i kontrola kosztu.
  • 06
    Halucynacje i weryfikacjaOgraniczanie błędów AI, weryfikacja generowanego kodu i bezpieczne wykonywanie operacji na produkcji.
  • 07
    Diagnostyka i logiAnaliza logów i zdarzeń, powtarzające się problemy techniczne, ręczna weryfikacja usług, raporty i skrypty administracyjne.
  • 08
    Review i analizyPrzegląd kodu oraz proste analizy dla biznesu zajmują najwięcej czasu; praca z bazami danych i systemami ERP.

05 · Środowisko

VM na kursie, własna stacja po kursie

na kursie

Ubuntu VM w chmurze dla wszystkich

5 osób nie może instalować oprogramowania na swoim komputerze, a 1 potrzebuje zgody. Wspólna maszyna wirtualna usuwa tę blokadę i daje wszystkim to samo środowisko:

  • Claude Code CLI, Node.js i Git gotowe do pracy
  • Ten sam projekt AI Chat i te same polecenia dla całej grupy
  • Brak wpływu na firmowe stacje robocze
POTEM
po kursie

Przeniesienie na własny komputer

11 z 14 osób pracuje na Windows. Po kursie ten sam workflow trzeba odtworzyć lokalnie lub na firmowej VM:

  • Claude Code natywnie w Windows albo w WSL2
  • Git, Node.js lub runtime własnego stosu
  • Zgoda IT na instalację i zasady przekazywania kodu do modelu
  • Konfiguracja agenta przeniesiona z repozytorium kursu

Dlaczego VM teraz

Ponad jedna trzecia grupy nie mogłaby zainstalować narzędzi samodzielnie. Jedna wspólna ścieżka pozwala pracować w tym samym tempie i pomagać sobie nawzajem.

Warunek wdrożenia

Dla osób bez prawa instalacji kluczowa jest rozmowa z IT o licencji, instalacji i polityce danych. Bez tego praktyki z kursu zostaną na VM.

06 · Rekomendacje

Następne kroki dla uczestników

1. Ustal zasady z IT

Potwierdź licencję, możliwość instalacji Claude Code (Windows lub WSL2) oraz zasady przekazywania kodu i danych firmowych do modelu.

2. Przenieś konfigurację agenta

Zabierz z repozytorium kursu instrukcje projektu, definicje agentów, skills i checklisty. Dopasuj je do własnego stosu i poleceń build/test.

3. Zacznij od testów i review

Pierwsze zadania w pracy: testy przed zmianą, review generowanego kodu i jasne kryteria akceptacji. To najszybciej ogranicza halucynacje.

4. Kontroluj koszt i pętle

Dobieraj model do zadania, ustaw limity tur i budżetu, przerywaj agenta bez postępu i zapisuj checkpointy.

5. Podłącz CI/CD

Użyj przykładu headless dla GitHub Actions lub GitLab CI na repozytorium testowym, zanim trafi do pipeline produkcyjnego.

6. Wybierz jedną własną automatyzację

Jeden powtarzalny proces: analiza logów, raport, skrypt administracyjny lub zapytanie SQL. Opisz go w PRD i zrealizuj z agentem.
