Moduł 1.2 | Tryby pracy

CLI interaktywny vs tryb -p

CLI interaktywny

  • Sesja dwukierunkowa, agent pamięta kontekst
  • Komendy / dostępne (/model, /compact itd.)
  • Można wglądać w pliki, edytować, iterować
  • Idealny do codziennej pracy i developmentu
claude

Tryb -p (print)

  • Nieinteraktywna praca, wynik do stdout
  • Domyślnie nowe zapytanie; --resume lub --continue pozwala kontynuować sesję
  • Można pipe'ować (wejście/wyjście)
  • Idealny do skryptów, CI/CD, automatyzacji
claude -p "przetłumacz README.md na angielski"
cat error.log | claude -p "wyjaśnij błąd"

1.2 / Desktop

Claude Desktop: Chat, Code i Cowork

Na przygotowanej VM Linux

  • Desktop jest zainstalowany; oficjalna wersja Linux ma status beta.
  • Chat służy rozmowie, Code pracy programistycznej; nie utożsamiaj czatu z uruchomieniem kodu w repozytorium.
  • Do ćwiczeń używamy przede wszystkim Claude Code CLI. Dostępne zakładki i uprawnienia sprawdź na swoim koncie.

Sandbox zależy od systemu

  • Cowork uruchamia zadania w osobnej VM. Na Linuxie potrzebuje KVM, QEMU i uprawnień do wirtualizacji.
  • Na maszynach kursowych (8 GB RAM) Cowork nie jest włączony. Nie instaluj ani nie zmieniaj hypervisora podczas ćwiczenia.
  • Hyper-V z programu dotyczy Windows. Sandbox poleceń Claude Code na Linuxie to osobny mechanizm.

Moduł 1.2 | Tryby pracy

Claude Web i remote environments

Praca w przeglądarce

  • Chmurowa sesja pracująca na repozytorium GitHub
  • Repo jest klonowane do izolowanej maszyny Anthropic
  • Zmiany trafiają na osobny branch i mogą zakończyć się pull requestem
  • Przydatne, gdy pracujesz na wielu maszynach

Remote Control i SSH

  • Remote Control pozwala sterować działającą sesją z innego urządzenia
  • SSH uruchamia sesję na wskazanym serwerze lub VM
  • To osobne mechanizmy od Claude Code Web
  • Uprawnienia i dostęp wynikają ze środowiska, w którym działa sesja
Na tym kursie pracujemy głównie w CLI na lokalnej VM. Web i Desktop jako uzupełnienie.
1.2 / tryby uprawnień

Plan i wykonanie: kontrolujesz zakres

  • W CLI wpisz /plan albo wybierz tryb Plan. Agent bada projekt i proponuje kroki przed edycją.
  • W zwykłej sesji poproś o konkretną zmianę i dowód: test, wynik i diff. Sama prośba o plan nie zastępuje uprawnień.
  • Zatwierdź wymagania i kontrakt, zanim zlecisz streaming lub zmiany UI.
  • Porównanie: podpowiedzi Copilota w IDE uzupełniają fragmenty. Claude Code CLI wykonuje zadania narzędziami w przyjętych granicach.

1.3 / konfiguracja

Instrukcje Claude Code w repozytorium

  • CLAUDE.md jest natywnym plikiem instrukcji Claude Code. Sprawdź treść i zakres przed pierwszą zmianą.
  • W tym repozytorium CLAUDE.md importuje @AGENTS.md: wspólne reguły mają jedno źródło. Sam AGENTS.md nie jest automatycznie odczytywany jako pamięć Claude Code.
  • Reguły dla ścieżek zapisz w .claude/rules/*.md z frontmatter paths; szczegóły katalogu mogą trafić do nested CLAUDE.md.
  • Porównanie: .github/copilot-instructions.md dotyczy Copilota, nie zastępuje CLAUDE.md.

Moduł 1.2 | Kluczowe komendy (1/2)

Zarządzanie sesją i kontekstem

/resume

Wznawia poprzednią sesję. Agent odtwarza kontekst, historię rozmowy i stan projektu.

Przydatne, gdy przerwałeś pracę i chcesz wrócić lub gdy przypadkowo zamknąłeś CLI.

/compact

Kompresuje kontekst sesji. Agent streszcza dotychczasową rozmowę, zachowując kluczowe informacje, a pomijając detale.

Stosuj, gdy sesja robi się długa i agent zaczyna gubić wątki (context rot).

/rewind

Cofa rozmowę (i opcjonalnie stan) do wybranego wcześniejszego punktu - użyj go, gdy Ty albo agent popełnił błąd i chcesz wrócić do momentu sprzed niego.

Wskazówka: /rewind Claude Code: przywraca rozmowę, pliki albo jedno i drugie (checkpointy obejmują zmiany z narzędzi edycji, nie efekty komend z Basha) - docs: checkpointing. GitHub Copilot CLI: /undo albo /rewind - rozmowa albo rozmowa i pliki zmienione przez Copilota - docs: roll-back. /compact skraca historię sesji. Codex ma /resume i /fork (rozmowa), bez cofania plików - docs: Codex CLI. Kod cofasz gitem w każdym narzędziu.
Moduł 1.2 | Kluczowe komendy (2/2)

Diagnostyka, modele i uprawnienia

/context

Pokazuje strukturę kontekstu agenta: co widzi (system prompt, CLAUDE.md, otwarte pliki, historia sesji).

Używaj, gdy agent dziwnie odpowiada - sprawdź, co naprawdę wie.

/model

Przełącza model (Opus / Sonnet / Haiku i inne dostępne modele). Porównaj jakość na własnym zadaniu, czas i zużycie; większy model nie gwarantuje poprawności.

Używaj, gdy potrzebujesz innej jakości lub innego kosztu do konkretnego zadania.

/permissions

Reguły uprawnień: allow (bez pytania), ask (zawsze pyta), deny (nigdy). Zapisywane w settings.json.

Używaj, gdy chcesz kontrolować, co agent może robić z Twoim systemem.

1.2 / ściąga

Komendy, których użyjesz na kursie

  • /help - lista komend Twojej wersji. /resume - powrót do zapisanej rozmowy, bez cofania repozytorium.
  • /context - wykorzystanie kontekstu; /compact - streszczenie rozmowy. Zapisz wcześniej decyzje w dokumentach.
  • /model - wybór modelu; /permissions - reguły narzędzi; /sandbox - izolacja poleceń.
  • /init - propozycja CLAUDE.md; /memory - pamięć; /mcp - serwery i zaufanie; /hooks - hooki.
  • /plan - planowanie; /agents w 2.1.302 wskazuje tworzenie definicji w plikach. Starszy kreator nie jest stałym interfejsem.
  • /doctor - diagnostyka. Własne komendy zapiszesz w .claude/commands/, np. git/commit.md jako /git:commit.

1.2 / modele i alternatywy

Alternatywne modele: GLM i lokalna Gemma 4

  • Opus: złożone decyzje i analiza; Sonnet: punkt startu do implementacji; Haiku: krótkie, dobrze ograniczone zadania. Weryfikuj wynik każdej rodziny.
  • Z.AI dokumentuje podłączenie GLM-5.3 do Claude Code przez zgodny endpoint Anthropic i mapowanie modeli. To inny dostawca, limity i warunki przetwarzania danych.
  • Ollama może udostępnić model przez API zgodne z Anthropic. Dla Gemma 4 sprawdź wariant, narzędzia, streaming i zasoby; sama zgodność formatu API nie dowodzi jakości całego agenta.
  • VM z 8 GB RAM nie jest obietnicą komfortowej lokalnej inferencji. To ścieżka dalszej nauki; nie pobieramy dużych modeli na kursie.

1.1 / środowisko

Ubuntu VM: pracuj w jednym środowisku

  • Terminal, Git, Node.js i katalog projektu są na przygotowanej VM. Nie przenoś ćwiczeń do przypadkowego folderu Windows.
  • Sprawdź pwd, git status, wersje narzędzi i dostęp do konta. Nie pokazuj zmiennych środowiskowych ani tokenów.
  • CLI działa w bieżącym katalogu z jego uprawnieniami. Przed zgodą na polecenie przeczytaj, jaki ma cel i jakie pliki zmieni.
  • Desktop i Web są alternatywnymi trybami. Sesja w chmurze ma osobny checkout, środowisko, sieć oraz poświadczenia.
  • Porównanie z Windows: Hyper-V/Cowork i WSL nie są wymaganiami Ubuntu VM. Zagnieżdżona wirtualizacja wymaga wsparcia administratora.
