Ściąga do pracy z Claude Code

Odpowiedzi pomagają przy ćwiczeniach. Pytania tej grupy uzupełniamy podczas zajęć. Dodatkowe karty porównawcze zachowują własne źródła i daty; nie opisują automatycznie Claude Code.

Krótka ściąga na pokaz i do wykorzystania po zajęciach. Najpierw pracujemy nad własnym projektem; te odpowiedzi pomagają wtedy, gdy pojawia się konkretna decyzja.

Jak wznowić sesję i cofnąć edycję w Claude Code?

/resume wznawia rozmowę, ale nie cofa repozytorium. /rewind korzysta z checkpointów rozmowy i edycji plików; nie odwraca automatycznie poleceń powłoki, push ani zewnętrznych działań. Sprawdź git status i diff; Git jest osobnym sposobem odzyskania kodu.

Jak odróżnić reguły narzędzi od sandboxu?

W .claude/settings.json używasz permissions.allow, ask i deny. W CLI flagi to --allowedTools i --disallowedTools. Przejrzyj je przez /permissions. Tryb planowania, akceptacja edycji i sandbox rozwiązują różne problemy: sandbox ogranicza pliki i sieć wykonywanych poleceń. Nie zakładaj, że sam Markdown blokuje wykonanie.

Dlaczego skill nie pojawia się w IntelliJ?

Sprawdź wersję pluginu GitHub Copilot, wybrany harness i panel Customizations. Obsługa skills w JetBrains jest nadal dostępna jako wersja testowa. Repozytoryjne .agents/skills/<nazwa>/SKILL.md jest oficjalną lokalizacją skills, ale wykrywanie zależy od powierzchni i konfiguracji. Jeśli nie widać skilla w Local, sprawdź Copilot harness; nie kopiuj od razu skilla do kolejnych miejsc.

W VS Code "Local" oznacza host rozszerzenia w edytorze, a nie model uruchomiony lokalnie. Copilot harness działa na Agent Host i korzysta z Copilot SDK. Sam SDK pozwala też budować własne aplikacje z silnikiem Copilot. Copilot CLI w terminalu i JetBrains AI Assistant przez ACP to kolejne odrębne interfejsy.

Źródła: GitHub - mapa customizacji, GitHub - JetBrains, JetBrains 1.18.0, VS Code - harnesses, GitHub - Copilot SDK.

Czy AGENTS.md działa automatycznie w Claude Code?

Claude Code natywnie korzysta z CLAUDE.md. W tym repozytorium plik zawiera @AGENTS.md, więc wspólne instrukcje są jawnie importowane. Dla ścieżek użyj .claude/rules/*.md z paths, a dla lokalnych konwencji zagnieżdżonego CLAUDE.md. Reguły kontekstu nie nadają uprawnień OS.

Co przechowywać między sesjami?

PRD przechowuje zachowanie produktu, ADR decyzje techniczne, a plan stan pracy i dowody. /resume wraca do rozmowy, /compact ją streszcza. Pamięć automatyczna i opcjonalne memory subagenta nie zastępują sprawdzonych dokumentów ani Git. Nie zapisuj w nich sekretów i treści prywatnych rozmów.

Co może ustawić organizacja, a co zrobić lokalnie?

Administratorzy mogą zarządzać częścią polityk Copilota, MCP i enterprise plugin standards. Nie ma w dokumentacji jednego uniwersalnego przełącznika "wymagaj tego skilla wszystkim". Nowy plugin JetBrains deklaruje obsługę skills organizacyjnych, lecz dokładną ścieżkę publikacji trzeba potwierdzić dla danej powierzchni.

Bezpośrednia instalacja pluginu z repozytorium nadal działa, ale jest oznaczona jako deprecated; dla pluginów preferowany jest marketplace. Publiczne pojedyncze skills z EdukeyTeam/agent-toolbox instalujemy zgodnie z instrukcją kursu. BYOK samo w sobie nie oznacza modelu lokalnego. Praca lokalna wymaga zaplecza uruchomionego na własnym urządzeniu lub w zatwierdzonym środowisku; zgodność z polityką firmy wymaga osobnej decyzji organizacji.

Źródła: GitHub - enterprise plugin standards, GitHub - plugin CLI, VS Code - language models.

Czy Copilot indeksuje repozytorium jak Cursor?

Tak. Narzędzie semantic search szuka kodu po znaczeniu, nie tylko po słowach. Agent używa go sam, gdy to pomaga; możesz je wskazać przez #codebase.

  • GitHub i Azure DevOps: indeks buduje się zdalnie i automatycznie.
  • Inne repozytoria: indeks lokalny, pierwsze budowanie trwa kilka minut. Dla kont organizacji jest domyślnie wyłączony i włącza go polityka Copilota.
  • Pomija pliki z .gitignore, files.exclude i search.exclude. Przebudowa: Build Codebase semantic index w palecie poleceń.

Agenci coraz lepiej radzą sobie zwykłym przeszukiwaniem plików (grep, ripgrep), więc indeks najbardziej pomaga w dużych repozytoriach i przy pytaniach o znaczenie ("gdzie liczymy rabat?").

Źródło: VS Code: workspace context.

Agent Host, harnessy i praca w WSL

W VS Code agent działa w jednym z dwóch miejsc. Local (Extension Host) to domyślny czat rozszerzenia Copilot. Agent Host to osobny proces, w którym działają harnessy Copilot (Copilot SDK), Claude i Codex. Tylko w Agent Host są m.in. Assisted permissions, sesje współdzielone między oknami i zdalne uruchamianie agenta.

Agent Host działa tam, gdzie workspace. Połącz VS Code z WSL (przycisk w lewym dolnym rogu, rozszerzenie WSL): agent i jego polecenia działają wtedy w Linuksie, nie w Windows. Tak samo przy SSH; w Dev Containers to wciąż funkcja eksperymentalna.

Źródła: VS Code: Agent Host, VS Code: harnesses.

Git worktrees bez instalowania wszystkiego od nowa

Każdy worktree potrzebuje własnego node_modules. Z pnpm prawie nic to nie kosztuje: pakiety leżą w jednym magazynie na dysku, a node_modules w worktree zawiera tylko linki. Włącz globalny wirtualny magazyn w pnpm-workspace.yaml:

virtualStoreType: global

W pnpm starszym niż 11.23 to enableGlobalVirtualStore: true. Pierwsze pnpm install pobiera pakiety, w kolejnych worktree instalacja trwa chwilę. npm i Yarn nie mają takiego mechanizmu: każdy worktree to pełna instalacja.

Jeden zapisywalny magazyn tylko dla agentów, którym ufasz w równym stopniu. Pozostałe koszty worktree zostają: osobne porty serwerów, kopia .env i sprzątanie przez git worktree remove.

Źródło: pnpm: git worktrees.

Hooki: czy można je ograniczyć do plików i poleceń?

Tak. Hook uruchamia się na zdarzeniu, np. przed każdym użyciem narzędzia (preToolUse w Copilocie, PreToolUse w Claude Code i Codex), i dostaje pełne argumenty wywołania: polecenie, ścieżkę pliku, wzorzec wyszukiwania. Zawęzisz go na trzy sposoby:

  • matcher: nazwa narzędzia jako wyrażenie regularne, np. Bash|Read,
  • if (Claude Code): składnia reguł uprawnień, np. Bash(git commit *),
  • skrypt: sam sprawdza plik lub polecenie i zwraca odmowę (kod wyjścia 2).

W repozytorium kursu jest jeden skrypt blokujący odczyt .env, kluczy SSH i secrets/ z konfiguracją dla Copilota, Claude Code i Codex. Hooki Copilota z .github/hooks/*.json działają w Copilot CLI, cloud agencie i VS Code (preview).

Źródła: GitHub: hooki, GitHub: hooks reference, VS Code: hooki, Claude Code: hooki, Codex: hooki.

Agent w CI/CD: Azure, GitLab, Bitbucket

Gotowy zestaw w repozytorium kursu: agent robi code review i security review każdego pull requestu, dodaje komentarz do PR, czyta zadanie z Jira i dopisuje tam wynik. Agenta wybierasz jedną zmienną: Copilot, Claude Code, Codex albo OpenCode.

  • Pipeline'y: Azure Pipelines, GitLab CI i Bitbucket Pipelines; dla GitHub Actions osobne przykłady w tym samym folderze.
  • Dostęp: najprościej jeden klucz OPENROUTER_API_KEY dla wszystkich agentów. Copilot na własnym koncie wymaga fine-grained PAT z uprawnieniem Copilot Requests, Claude Code ANTHROPIC_API_KEY, Codex CODEX_API_KEY.
  • Obraz: własny, na Debian slim z czterema CLI. Alpine odpada, bo narzędzia agentów zakładają glibc.
  • Bitbucket: app passwords przestały działać w lipcu 2026; użyj access tokena repozytorium.

Źródła: Copilot CLI programowo, Claude Code headless, Codex exec, Bitbucket API tokens.
